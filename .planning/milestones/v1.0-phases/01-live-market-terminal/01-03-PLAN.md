<objective>
Turn the working-but-plain skeleton into the Bloomberg-style terminal the product promises: the dark theme, live price flashes, per-row sparklines, and a large chart for whichever ticker the user clicks.

**User story (MVP):** **As a** trader scanning the market, **I want to** see price movement at a glance — flashing rows, per-ticker sparklines, and a full chart for whatever I click — **so that** I can read the market from the screen instead of reading numbers.

Purpose: This is the phase's last slice and the only one whose value is entirely visual. It also establishes the theme tokens and the charting conventions that Phases 2 and 3 reuse for the heatmap, the P&L chart, and the chat panel — so the token names and the Lightweight Charts wrapper are a contract, not decoration.

Output: Tailwind v4 `@theme` tokens and flash keyframes in `app/globals.css`, `Sparkline.tsx` (inline SVG, no library), `PriceChart.tsx` (Lightweight Charts v5), a fully rendered `WatchlistPanel.tsx`, and a human-verified terminal.
</objective>

**B. `frontend/hooks/usePriceStream.ts` — add a chart-ready buffer.** Alongside the existing numeric
`history` buffer, accumulate `timeline: Record<string, {time: number; value: number}[]>`. Lightweight
Charts requires time values that are strictly ascending and unique; SSE frames arrive roughly every
500ms, so `Math.floor(tick.timestamp)` produces duplicate seconds and occasionally a value not greater
than the last one. Before appending, floor the timestamp to whole seconds and: replace the last entry
when the floored time equals the last entry's time, drop the point entirely when it is less than the
last entry's time, and append otherwise. Cap this buffer at the same 120 entries as `history` and slice
from the end so the oldest points fall off first. This dedupe is what prevents the library from throwing
on out-of-order data.

**C. `frontend/components/PriceChart.tsx`.** `'use client'` — chart creation touches the DOM directly
and cannot run during the static export's build-time prerender.
  - Props `{ ticker: string | null; points: { time: number; value: number }[] }`.
  - In a `useEffect` keyed on nothing but mount, create the chart once with `createChart(containerRef
    .current, {...})`, then `chart.addSeries(LineSeries, { color: '#209dd7', lineWidth: 2 })`. Import
    `createChart`, `LineSeries`, and the `IChartApi`/`ISeriesApi` types as named exports. This is the v5
    API — the `chart.addLineSeries()` form shown in most tutorials does not exist in 5.x and fails at
    runtime.
  - Theme the chart from the same palette: transparent or panel-colored background, muted gray grid
    lines and borders, accent-blue series, and the terminal foreground for axis text. Enable the time
    scale with seconds visible, since the whole series spans minutes.
  - In a second `useEffect` keyed on `[ticker, points]`, call `series.setData(points)`. Use `setData`
    rather than `update` so switching tickers replaces the series wholesale instead of appending one
    ticker's prices onto another's. With zero or one point, `setData` on an empty or single-element array
    is valid and renders the axes with no line — do not guard it away with an early return that unmounts
    the chart.
  - Resize with a `ResizeObserver` on the container calling `chart.applyOptions({ width })`.
  - Cleanup: `chart.remove()` and null the refs, so a fast-forward through several tickers cannot leak
    canvases.
  - When `ticker` is null, render the empty chart frame with a short prompt to pick a ticker — keep the
    container mounted so the chart is not torn down and rebuilt on every selection.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE payload -> React render | Server-supplied ticker strings and numeric fields become DOM content |
| user input -> DOM | The add-ticker input value is echoed back in inline status messages |
| npm registry -> frontend bundle | `lightweight-charts` executes in the browser as part of the shipped bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-14 | Tampering | rendering `prices` and the inline duplicate message | medium | mitigate | Render every value as a JSX text child, which React escapes; no `dangerouslySetInnerHTML` anywhere in the frontend. The `Sparkline` `points` prop is typed `number[]` and used only in numeric coordinate math, never as markup. |
| T-01-15 | Denial of Service | unbounded client-side accumulation of `history` and `timeline` | medium | mitigate | Both buffers are capped at 120 entries per ticker and sliced from the end, so a session left open overnight cannot exhaust browser memory. The `timeline` dedupe additionally drops duplicate-second points before they are stored. |
