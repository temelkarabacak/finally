<objective>
Make the portfolio legible at a glance: a positions table with live P&L and a treemap where every holding is sized by its weight and colored by whether it is winning or losing.

**User story (MVP):** **As a** trader holding several positions, **I want to** see them as a table and as a weighted heatmap, **so that** I can spot my concentration and my losers without doing arithmetic in my head.

Purpose: This is the last slice of Phase 2 and the only one whose value is entirely visual. It also converges the three ticker surfaces — watchlist, positions table, heatmap — onto the single `selectedTicker` state `page.tsx` already owns (D-05, D-06), so clicking anywhere drives the main chart and readies the trade bar. It introduces the phase's only new dependency, `recharts`, behind a blocking legitimacy gate.

Output: `PositionsTable.tsx`, `PortfolioHeatmap.tsx`, the completed `page.tsx` layout, and `recharts` in `frontend/package.json`.
</objective>

**B. `frontend/components/PortfolioHeatmap.tsx`.** `'use client'` — Recharts measures the DOM through a
`ResponsiveContainer`, which cannot run during the static export's build-time prerender, exactly like
`lightweight-charts`. Props are `{ positions: PositionView[]; loaded: boolean; selected: string | null;
onSelect: (ticker: string) => void }`.

Panel chrome matches the other panels: `rounded border border-terminal-border bg-terminal-panel p-3`
with an `text-sm font-semibold uppercase tracking-wide text-accent-yellow` heading reading "Heatmap".

Empty state (D-02): when `positions.length === 0`, whether truly empty or not yet loaded, render the
identical centered `text-terminal-muted` block used by the positions table — heading "No positions yet",
body "Buy shares to get started." — in place of the treemap. Do not mount the treemap with an empty
dataset; Recharts' layout of zero nodes is not a useful visual.

Otherwise map each position to a node `{ ticker, weight: market_value, pnl: unrealized_pnl, pnlPercent:
unrealized_pnl_percent }` and render `<ResponsiveContainer><Treemap data={nodes} dataKey="weight"
content={<HeatmapCell .../>} isAnimationActive={false} /></ResponsiveContainer>`. `dataKey="weight"`
is what sizes each rectangle by that position's share of total holdings value; leave the sizing to the
library rather than computing rectangles by hand. Disable animation so a tile does not re-tween on every
price tick.

`HeatmapCell` is a function component receiving Recharts' injected `{ x, y, width, height, index }` plus
your own props. It renders a `<g>` containing:
  - a `<rect>` filled from the P&L sign: `#3fb950` when `pnl > 0`, `#f85149` when `pnl < 0`, and the
    muted border grey at exactly zero, with a `#0d1117` stroke roughly 2px wide to separate tiles;
  - the selected tile additionally takes an `#209dd7` stroke at roughly 3px, so selection reads the same
    blue as the watchlist and positions rows (D-08);
  - two `<text>` elements in `#e6edf3` — the ticker and the signed percent change to two decimals.
    The percent label is what keeps profit and loss legible when the fill colour is unavailable, so it
    is not optional decoration.
  - When either `width` or `height` is below 24 the text elements are omitted entirely rather than
    drawn and clipped — a label wider than its tile overlaps its neighbour and makes both unreadable.
  - `onClick` on the `<g>` calls `onSelect(ticker)`, satisfying D-06; give it `cursor-pointer` styling
    and an `aria-label` naming the ticker and its P&L so the tile is not a mouse-only affordance.

A single position produces one tile filling the panel, which is native `Treemap` behaviour — do not
special-case it.

Take colour values from the CSS custom properties where a Tailwind class can carry them, and use the
literal hex values above where an SVG `fill`/`stroke` attribute needs a concrete string; both must stay
in sync with `frontend/app/globals.css`.
