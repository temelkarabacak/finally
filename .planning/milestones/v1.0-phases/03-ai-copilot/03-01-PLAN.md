sends a message, and gets back one complete, portfolio-grounded assistant reply rendered inline —
persisted to `chat_messages` with the exact write ordering CHAT-04 requires, and switchable to a
deterministic offline matcher via `LLM_MOCK=true`.

**User story (MVP):** **As a** FinAlly trader, **I want to** ask an AI assistant about my
portfolio from inside the terminal, **so that** I get analysis grounded in my real cash,
positions, and live prices without leaving the app.

Purpose: prove the whole architecture — LiteLLM/OpenRouter/Cerebras call, structured-output
contract, transaction discipline around the one unavoidable `await`, router factory wiring, and
the drawer UI — on one path before any of it is expanded. An architectural dead end surfaces
after one commit instead of after ten.

Output: `backend/app/llm/` (contract, prompt, client, mock, persistence, router), the chat route
mounted in `main.py`, `frontend/hooks/useChat.ts` + the drawer component tree wired into
`app/page.tsx`, and the vitest harness the rest of the phase's frontend tests depend on.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/chat` | Untrusted free-text user input crosses into the server |
| backend → OpenRouter/Cerebras | Outbound network call carrying portfolio figures and bearing `OPENROUTER_API_KEY` |
| LLM response → application state | Untrusted model output crosses into a parser and (from 03-02) into state-changing operations |
| application → SQLite (`chat_messages`) | Single-writer database shared with the trade path and the 30s snapshot task |
