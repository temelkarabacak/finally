<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process → network | A test that silently reaches a real API or a real LLM turns a hermetic suite into a flaky, key-dependent one |
| test fixtures → developer database | A test that writes to the real `db/finally.db` destroys the developer's portfolio state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-14 | Tampering | `backend/tests/**` — database targeting | medium | mitigate | Every test obtains its connection through the `initialized_db` fixture, which points `FINALLY_DB_PATH` at a `tmp_path` file and resets the module-level connection singleton before and after; no test opens `db/finally.db` |
| T-03-15 | Information Disclosure | `frontend/**/*.test.tsx` — network access from tests | medium | mitigate | Every frontend test stubs `global.fetch` with `vi.fn()`; no test issues a real request, so the suite cannot leak state or depend on a running backend |
| T-03-16 | Denial of Service | `frontend/package.json` test script | low | mitigate | The script is `vitest run`, not bare `vitest`, so `npm test` exits with a status code instead of hanging forever in watch mode in CI or in an agent's shell |
</threat_model>
