<objective>
Package the completed FinAlly app into one Docker image that serves the static frontend, the REST API, the SSE stream, and the AI chat on port 8000, with the SQLite database living in the host's bind-mounted `db/` directory so a portfolio survives stop/start.

Purpose: DEPLOY-01 and DEPLOY-02 are the foundation of this phase — the lifecycle scripts (04-02) and the E2E harness (04-03/04-04) both build on this image. Two one-line configuration facts in this plan (`FINALLY_DB_PATH`, `timeout-graceful-shutdown`) fail *silently* if missed: the app builds, runs, and looks correct while writing the database outside the mount or hanging on every stop.

Output: `Dockerfile`, `.dockerignore`, `db/.gitkeep`, `scripts/verify_container.sh`, and a bounded-shutdown patch to `scripts/smoke.sh`.
</objective>

Create `.dockerignore` at the repo root first, then `Dockerfile` at the repo root.

`.dockerignore` excludes, at minimum: `.git`, `.github`, `.env`, `.env.*`, `.planning`, `planning`, `.claude`, `.gsd`, `node_modules`, `frontend/node_modules`, `frontend/.next`, `frontend/out`, `frontend/tsconfig.tsbuildinfo`, `backend/.venv`, `backend/static`, `backend/tests`, `**/__pycache__`, `*.pyc`, `db`, `test`. Two of these are load-bearing rather than size trimming: excluding `.env` and `.env.*` is what keeps `OPENROUTER_API_KEY` and `MASSIVE_API_KEY` out of every image layer (they arrive at run time via `--env-file` only), and excluding `backend/static` prevents a stale local export from merging with the fresh one produced by the build stage. Do not exclude `frontend/package.json`, `frontend/package-lock.json`, `backend/pyproject.toml`, `backend/uv.lock`, or `backend/README.md` — all four are needed by the build stages (`readme = "README.md"` in `pyproject.toml` makes the README a build input).

`Dockerfile` has exactly three stages, following 04-RESEARCH.md Pattern 1:

Stage `frontend-builder` from `node:20-slim`, workdir `/fe`: copy `frontend/package.json` and `frontend/package-lock.json`, run `npm ci`, copy the rest of `frontend/`, run `npm run build`. The static export lands at `/fe/out`.

Stage `backend-builder` from `python:3.12-slim`, workdir `/app`: bring in the uv binaries with `COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/`, set `ENV UV_PYTHON_DOWNLOADS=0` so uv uses the base image's interpreter instead of downloading its own, copy `backend/pyproject.toml` and `backend/uv.lock`, run `uv sync --locked --no-install-project` behind a `--mount=type=cache,target=/root/.cache/uv` cache mount, then copy the whole of `backend/` into `/app` (contents flattened, so `main.py` lands at `/app/app/main.py`), then run `uv sync --locked` again. Finally `COPY --from=frontend-builder /fe/out ./static` so the export lands at `/app/static` — this exact directory name and depth is required because `app.frontend()` resolves `parents[1] / "static"` from `/app/app/main.py`. Do not rename or relocate it.

Stage 3 (runtime, unnamed) from `python:3.12-slim` — the identical base tag as `backend-builder`, never Astral's trixie-based `astral-sh/uv:python3.12-*` image, because a Debian-suite mismatch between the venv-building stage and the runtime stage produces a `GLIBC` failure the first time numpy is imported. Workdir `/app`, `COPY --from=backend-builder /app /app`, `ENV PATH="/app/.venv/bin:$PATH"`.

Set `ENV FINALLY_DB_PATH=/app/db/finally.db` explicitly in this stage. This is not optional convenience: `resolve_db_path()`'s fallback computes `Path(__file__).resolve().parents[3]`, which from `/app/app/db/connection.py` resolves to the filesystem root, so without this env var the container silently writes its database to `/db/finally.db` in the throwaway writable layer and every restart resets the portfolio while the host's `db/finally.db` looks fine.

`EXPOSE 8000`. Add a `HEALTHCHECK` with `--interval=10s --timeout=3s --start-period=5s --retries=3` whose command is a `python -c` one-liner using `urllib.request` against `http://localhost:8000/api/health` and exiting non-zero unless the status is 200 — use the interpreter already on `PATH` rather than installing `curl` or `wget`, neither of which exists in the `slim` base.

`CMD` is the exec-form list `uvicorn app.main:app --host 0.0.0.0 --port 8000 --timeout-graceful-shutdown 10`. The `--timeout-graceful-shutdown 10` flag is required, not cosmetic: uvicorn's default is unbounded, and the SSE generator in `backend/app/market/stream.py` only breaks its loop on *client* disconnect, so an open stream makes shutdown wait forever — the hang already reproduced twice against `scripts/smoke.sh` per STATE.md's Phase 4 blocker entry.

Never add a build-time instruction that copies an environment file into the image.

Use image name `finally`, container name `finally-verify`, host port `8010` mapped to container port `8000` (never 8000 on the host, so the gate is safe to run while the user's own `finally-app` container is up), and a `mktemp -d` host directory bind-mounted at `/app/db` (never the real `db/` directory, so a verification run cannot touch the developer's portfolio). Run the container with `LLM_MOCK=true` and `--stop-timeout 15`. Install an `EXIT` trap that bounded-stops the verify container, deletes it, and deletes the temp directory; make the trap tolerant of a container that is already gone so the script is safe to re-run.

The gate's assertion sequence, each failing loudly with a `FAIL:` message and a non-zero exit:

1. `docker build -t finally .` from `REPO_ROOT`.
2. Start the container, then poll `/api/health` on 8010 with the same 40 x 0.5s loop `smoke.sh` uses.
3. Assert the health body equals `{"status":"ok","market_source":"simulator"}`.
4. Assert `GET /` contains `terminal-root` and `GET /api/watchlist` returns 10 entries.
5. Assert the SSE stream emits a `data:` frame containing `"direction"`.
6. Assert the temp host directory now contains `finally.db` — this is the DEPLOY-02 bind-mount proof, and it is exactly what silently fails if `FINALLY_DB_PATH` is not set in the image.
7. Execute a buy through the API: `POST /api/portfolio/trade` with `{"ticker":"AAPL","quantity":1,"side":"buy"}`, then capture `cash_balance` and the AAPL position quantity from `GET /api/portfolio`.
8. Open a background SSE reader against `/api/stream/prices` so a long-lived connection is live, record the wall-clock seconds around `docker stop --timeout 15 finally-verify`, and assert the elapsed time is under 20 seconds. This is the bounded-shutdown proof; a hang here means the image's `--timeout-graceful-shutdown` is missing or the run lacked `--stop-timeout`.
9. `docker start finally-verify`, poll `/api/health` again, re-read `GET /api/portfolio`, and assert `cash_balance` and the AAPL position quantity are identical to the values captured in step 7. This is the DEPLOY-02 restart-persistence proof.
10. Print `==> All container verification assertions passed`.

Use `curl` for HTTP (as `smoke.sh` does) and `python3 -c` for JSON comparison rather than assuming `jq` is installed. Make the whole script idempotent: a leftover `finally-verify` container from an aborted earlier run must be bounded-stopped and removed before the fresh run starts, not treated as an error.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host `.env` → container process env | Secrets cross here at `docker run` time only; they must never cross at `docker build` time |
| container writable layer → host `db/` bind mount | The only durable data path; a misrouted DB path silently discards user state |
| host Docker daemon → container lifecycle signals | SIGTERM/SIGKILL crossing into a process holding long-lived SSE connections |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | Dockerfile / build context | high | mitigate | `.dockerignore` excludes `.env` and `.env.*`; no build instruction copies an environment file; verified by asserting `/app/.env` does not exist inside the built image |
| T-04-02 | Tampering | SQLite path resolution (`backend/app/db/connection.py`) | high | mitigate | `ENV FINALLY_DB_PATH=/app/db/finally.db` in the runtime stage; verified by asserting the bind-mounted host directory contains `finally.db` after startup |
| T-04-03 | Denial of Service (self-inflicted) | uvicorn shutdown with open SSE connections | medium | mitigate | `--timeout-graceful-shutdown 10` in `CMD`, paired with `--stop-timeout 15` at run time; verified by timing a stop with a live stream |
| T-04-04 | Elevation of Privilege | container default user (root) | low | accept | Single-user, localhost-only educational deployment; a hardcoded non-root UID breaks writes to a bind mount owned by an arbitrary host user (04-RESEARCH.md Open Question 2). Revisit before any non-local deployment. |
