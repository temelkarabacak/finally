<objective>
Stand the whole application up end to end for the first time: a real SQLite database that lazily creates and seeds itself, a FastAPI entry point that wires the already-built market-data subsystem into a running server, and a Next.js static export served from that same server on port 8000 showing live-streaming prices.

**User story (MVP):** **As a** trader opening FinAlly for the first time, **I want to** launch one command and immediately see live prices for a default set of tickers, **so that** I have a working market terminal before I have configured anything at all.

Purpose: This is the Walking Skeleton. Every remaining phase — trading, AI chat, containerization — builds on the exact wiring decisions made here. Getting the shared `PriceCache` instance, the lazy DB init, and the static-export serving contract right now is what makes Phases 2-4 additive rather than corrective.

Output: A runnable full stack — `backend/app/db/` (schema + seed + connection), `backend/app/main.py`, a scaffolded `frontend/` producing a static export, `scripts/dev.sh` + `scripts/smoke.sh`, and the backend test suite covering health, lazy init, seed data, startup wiring, and static serving.
</objective>

**B. `backend/app/db/schema.sql`** — six `CREATE TABLE IF NOT EXISTS` statements transcribed from
`planning/PLAN.md` section 7, no additions and no omissions:
`users_profile(id TEXT PRIMARY KEY, cash_balance REAL NOT NULL DEFAULT 10000.0, created_at TEXT NOT NULL)`;
`watchlist(id TEXT PRIMARY KEY, user_id TEXT NOT NULL DEFAULT 'default', ticker TEXT NOT NULL, added_at TEXT NOT NULL, UNIQUE(user_id, ticker))`;
`positions(id TEXT PRIMARY KEY, user_id TEXT NOT NULL DEFAULT 'default', ticker TEXT NOT NULL, quantity REAL NOT NULL, avg_cost REAL NOT NULL, updated_at TEXT NOT NULL, UNIQUE(user_id, ticker))`;
`trades(id TEXT PRIMARY KEY, user_id TEXT NOT NULL DEFAULT 'default', ticker TEXT NOT NULL, side TEXT NOT NULL CHECK(side IN ('buy','sell')), quantity REAL NOT NULL, price REAL NOT NULL, executed_at TEXT NOT NULL)`;
`portfolio_snapshots(id TEXT PRIMARY KEY, user_id TEXT NOT NULL DEFAULT 'default', total_value REAL NOT NULL, recorded_at TEXT NOT NULL)`;
`chat_messages(id TEXT PRIMARY KEY, user_id TEXT NOT NULL DEFAULT 'default', role TEXT NOT NULL CHECK(role IN ('user','assistant')), content TEXT NOT NULL, actions TEXT, created_at TEXT NOT NULL)`.
Timestamps are ISO-8601 strings. `positions`, `trades`, `portfolio_snapshots`, and `chat_messages` stay
empty this phase — they exist so `get_active_tickers()` can be written correctly today.

**C. `backend/app/db/seed.py`** — mirror the flat-constants shape of `app/market/seed_prices.py`.
Define `DEFAULT_USER_ID = "default"`, `DEFAULT_CASH_BALANCE = 10000.0`, and `DEFAULT_WATCHLIST` as the

**D. `backend/app/db/connection.py`** — plain functions, no class hierarchy, module-level
`logger = logging.getLogger(__name__)`, `from __future__ import annotations`.
  - `resolve_db_path() -> Path`: `FINALLY_DB_PATH` env var if set, else
    `Path(__file__).resolve().parents[3] / "db" / "finally.db"`. Create the parent directory with
    `mkdir(parents=True, exist_ok=True)`.
  - `init_db(db_path=None) -> None`: connect with `sqlite3.connect(path, check_same_thread=False,
    autocommit=True)`, apply `PRAGMA journal_mode=WAL` and `PRAGMA foreign_keys=ON`, then read
    `schema.sql` from `Path(__file__).parent / "schema.sql"` and `executescript` it. Because every
    statement is `IF NOT EXISTS`, running it against an existing database is a no-op. Seed ONLY when
    `SELECT COUNT(*) FROM users_profile` returns 0 — an existing database with rows is never re-seeded
    and never truncated. Store the connection in a module-level singleton returned by `get_db()`.
  - `get_active_tickers(conn, user_id=DEFAULT_USER_ID) -> list[str]`: run the real union now, even
    though `positions` is empty until Phase 2 —
    `SELECT ticker FROM watchlist WHERE user_id = ? UNION SELECT ticker FROM positions WHERE user_id = ? AND quantity > 0`.
    `UNION` (not `UNION ALL`) is what makes a ticker held *and* watched appear exactly once.
  - `get_watchlist_tickers(conn, user_id=DEFAULT_USER_ID) -> list[str]`: watchlist rows ordered by
    `added_at`.
  Bind every `user_id` and `ticker` value with `?` placeholders — SQL text is always a literal string in
  source, values only ever arrive through the parameter tuple (threat `T-01-01`).

**F. `backend/app/main.py`** — the entry point. Construct exactly ONE `PriceCache()` at module scope and
thread that same object everywhere; a second instance silently splits SSE from watchlist reads (this is
the phase's most dangerous mistake). Order matters:
  1. module scope: `cache = PriceCache()`, then `source = create_market_data_source(cache)`
  2. `lifespan(app)`: `init_db()`; `conn = get_db()`; `tickers = get_active_tickers(conn)`;
     `await source.start(tickers)`; put `cache`, `source`, `conn` on `app.state`; `yield`;
     `await source.stop()`; close the connection.
  3. `app = FastAPI(lifespan=lifespan, title="FinAlly")`
  4. `@app.get("/api/health")` returning `{"status": "ok"}` — read-only, touching neither the database
     nor the source, so it stays a truthful liveness probe under concurrency.
  5. `app.include_router(create_stream_router(cache))` — pass the module-scope `cache`.
  6. LAST: `app.frontend("/", directory=Path(__file__).resolve().parents[1] / "static",
     fallback="index.html", check_dir=False)`. Registering it last is what guarantees `/api/*` routes
     win; `check_dir=False` keeps the module importable by pytest before any frontend build exists.
  Add `GET /api/watchlist` here for now (WATCH-01 read path only): read `get_watchlist_tickers(conn)`
  and return a list of `{ticker, price, previous_price, change, change_percent, direction}` built from
  `cache.get(ticker)`, with `price` set to `null` for a ticker the cache has not seen yet. Plan 01-02
  moves this into `app/watchlist/router.py` and adds the mutation routes.
  Module-level logger, `from __future__ import annotations`, 100-char lines.
