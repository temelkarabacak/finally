**User story (MVP):** **As a** trader who just bought in, **I want to** see my total portfolio value plotted over time, **so that** I can tell at a glance whether the session is going my way.

Per D-04 the recorder starts at app startup rather than waiting for a first trade, so the chart's empty state resolves within about a minute for every user, traded or not. It also finishes TEST-01 by covering the P&L arithmetic and the HTTP contract that Plan 02-01's trade tests did not reach.

Output: the 30-second snapshot task wired into `lifespan`, `GET /api/portfolio/history`, `PnlChart.tsx`, and three new backend test modules.

**A. `backend/app/portfolio/snapshots.py` — add the loop and the query.** Keep `record_snapshot` exactly
as Plan 02-01 wrote it. Add module constants `SNAPSHOT_INTERVAL_SECONDS = 30.0` and
`HISTORY_LIMIT = 2000`, plus a module logger.

`get_snapshot_history(conn, user_id=DEFAULT_USER_ID, limit=HISTORY_LIMIT) -> list[dict]` selects
`total_value, recorded_at, id` from `portfolio_snapshots` for the user. Take the most recent `limit`
rows but return them oldest first, and make the ordering total by sorting on `recorded_at` with `id` as
the tie-break — two snapshots written in the same millisecond (the 30-second tick landing on a trade)
have identical `recorded_at`, and without the second sort key their relative order is whatever SQLite
happens to return. Each returned dict is `{"time": <recorded_at parsed to integer unix seconds>,
"value": <total_value>, "recorded_at": <the original ISO string>}` — `time` is what the charting
library consumes, `recorded_at` is kept so nothing downstream has to reverse the conversion. Parse with
`datetime.fromisoformat(...).timestamp()`; the stored strings are UTC-aware ISO-8601 written by
`datetime.now(UTC).isoformat()`.

`async def _snapshot_loop(get_conn, cache, interval)` runs `while True`: `await asyncio.sleep(interval)`
first, then `record_snapshot(conn, compute_total_value(conn, cache))`. Sleeping before the first write
means startup does not double up with any snapshot a trade writes in the first instants. Wrap the body
in `try/except asyncio.CancelledError: raise` and a broad `except Exception` that logs at error level
and continues to the next interval — one bad iteration must not silently kill the recorder for the rest
of the run, which is the same convention the market data polling loops already follow.

`start_snapshot_task(get_conn, cache, interval=SNAPSHOT_INTERVAL_SECONDS) -> asyncio.Task` returns
`asyncio.create_task(_snapshot_loop(...), name="portfolio-snapshot-loop")`.
`async def stop_snapshot_task(task) -> None` returns immediately when `task` is `None`, otherwise
cancels it and awaits it inside `try/except asyncio.CancelledError`, mirroring how the market data
sources shut their background tasks down.

Keep every SQLite call in this module synchronous and direct — no thread-pool offload. The loop's only
suspension point is its `asyncio.sleep`, which is precisely what guarantees it cannot land a write
between a trade's `BEGIN` and its `COMMIT` on the single-threaded event loop.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| background task → SQLite | An unattended writer runs for the life of the process against the shared connection |
| `GET /api/portfolio/history` → browser | An unbounded table becomes a response payload |
| snapshot rows → charting library | Stored timestamps become time values the library validates |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Denial of Service | unbounded `portfolio_snapshots` growth at 2 rows/minute forever | medium | mitigate | `get_snapshot_history` caps the response at `HISTORY_LIMIT = 2000` most-recent rows, so response size is bounded regardless of table size. Row retention itself is accepted at this scale (~1MB/year for a single-user simulated portfolio) and is not pruned. |
| T-02-10 | Denial of Service | a snapshot loop iteration raising and killing the recorder for the rest of the run | medium | mitigate | The loop body catches and logs non-cancellation exceptions and continues to the next interval; `asyncio.CancelledError` is re-raised so shutdown still works. Task 1 covers this with a `get_conn` that raises once. |
| T-02-11 | Tampering | the background writer landing inside a trade's open transaction | high | mitigate | The loop's only suspension point is `asyncio.sleep`, and the trade transaction contains no await, so on the single-threaded event loop neither can interleave with the other. No SQLite call in this module is offloaded to a thread. |
| T-02-12 | Denial of Service | the loop writing to a closed connection during shutdown | medium | mitigate | `stop_snapshot_task` is awaited in `lifespan` before `source.stop()` and before `conn.close()`, so the task is fully cancelled and awaited before its dependencies disappear. |
| T-02-13 | Information Disclosure | history endpoint exposing internal row ids or file paths | low | accept | The response carries only `time`, `value`, and the ISO `recorded_at`; the row `id` is used for sort stability and is not serialized. Single-user app with no authorization boundary at ASVS L1. |
| T-02-14 | Tampering | snapshot values rendered into the DOM | low | mitigate | Values are numbers rendered through the charting library's typed API and, for the error branch, a JSX text child that React escapes. |
| T-02-SC | Tampering | package-manager installs | n/a | accept | This plan adds no npm or Python package; `lightweight-charts` is already installed and was cleared by the Phase 1 legitimacy checkpoint. |
</threat_model>
